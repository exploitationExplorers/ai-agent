naive-rag.mjs 代码分析报告

该脚本实现了一个最小可运行的 LangGraph + Milvus 检索增强生成（RAG）流程，面向《天龙八部》问答场景。

1) 整体架构

START
→
retrieve
→
generate
→
END

图中流程与代码中的 StateGraph 一致：先向量检索，再基于片段流式生成答案。

2) 核心模块拆解

模型层

  • ChatOpenAI 使用 qwen-plus。
  • 从环境变量读取 OPENAI_BASE_URL 与 OPENAI_API_KEY。
  • 在 generateNode 里通过 model.stream() 输出流式文本。

向量检索层

  • OpenAIEmbeddings 维度设为 1024。
  • 连接 Milvus 集合 ebook_collection。
  • 检索函数 similaritySearchWithScore(question, k) 并格式化元数据。

图编排层

  • State: question/k/documents/generation。
  • 节点: retrieveNode 与 generateNode。
  • 调用: graph.invoke() 触发完整链路。

输出层

  • 先打印 Mermaid 图（便于可视化流程）。
  • 再打印检索片段（相似度、章节、内容摘要）。
  • 最后输出流式生成结果。

3) 逐段代码释义（更详细）

片段 A（L1-L4）导入依赖

import "dotenv/config";
import { ChatOpenAI, OpenAIEmbeddings } from "@langchain/openai";
import { Annotation, END, START, StateGraph } from "@langchain/langgraph";
import { Milvus } from "@langchain/community/vectorstores/milvus";
  • 含义：加载环境变量、模型能力、图编排能力、Milvus 向量库适配器。
  • 为什么这样写：将“配置加载”和“业务能力”在入口一次性准备，后续逻辑更干净。
  • 注意：Milvus 会间接依赖 @zilliz/milvus2-sdk-node。

片段 B（L6-L14）常量与图状态定义

const COLLECTION_NAME = "ebook_collection";
const TOP_K = 5;

const GraphState = Annotation.Root({
  question: Annotation,
  k: Annotation,
  documents: Annotation,
  generation: Annotation,
});
  • 含义：固定集合名与默认召回条数，并声明图节点间传递的数据结构。
  • 输入输出：这里本身无运行时输入，属于“全局配置与 schema”。
  • 价值：让 retrieve 与 generate 通过统一 state 通信。

片段 C（L16-L30）模型与嵌入初始化

const model = new ChatOpenAI({ ... });
const embeddings = new OpenAIEmbeddings({ ... });
let vectorStore;
  • 含义：准备对话模型、Embedding 模型，并预留向量库实例变量。
  • 输入：OPENAI_BASE_URL、OPENAI_API_KEY 环境变量。
  • 副作用：若环境变量缺失，后续请求模型时会失败。

片段 D（L32-L50）检索函数 retrieveRelevantContent

async function retrieveRelevantContent(question, k = TOP_K) {
  const docsWithScores = await vectorStore.similaritySearchWithScore(question, k);
  return docsWithScores.map(([doc, score]) => ({ ... }));
}
  • 含义：把“用户问题”变成向量检索请求，返回结构化片段列表。
  • 输入：question（问题）、k（召回数）。
  • 输出：数组，每项包含 score/content/book_id/chapter_num/index。
  • 容错：异常时打印错误并返回空数组，避免图执行直接中断。

片段 E（L52-L61）图节点 retrieveNode

const retrieveNode = async (state) => {
  console.log(state, "state");
  const documents = await retrieveRelevantContent(state.question, state.k);
  return { question: state.question, k: state.k, documents };
};
  • 含义：这是图中的“检索节点”，读取 state 并补全 documents。
  • 输入：state 的 question 和 k。
  • 输出：新的 state（含检索结果）。
  • 备注：console.log(state) 是调试输出，可在稳定后去掉。

片段 F（L63-L105）图节点 generateNode

const context = state.documents.map(...).join(...);
const prompt = `...${context}...${state.question}...`;
const stream = await model.stream(prompt);
for await (const chunk of stream) { ... }
  • 含义：把检索片段拼成上下文，构造提示词，流式调用模型生成回答。
  • 输入：documents 与 question。
  • 输出：generation（完整回答文本）。
  • 副作用：实时向控制台写流式 token（用户能边生成边看到结果）。

片段 G（L107-L113）图编排定义

const graph = new StateGraph(GraphState)
  .addNode("retrieve", retrieveNode)
  .addNode("generate", generateNode)
  .addEdge(START, "retrieve")
  .addEdge("retrieve", "generate")
  .addEdge("generate", END)
  .compile();
  • 含义：声明固定执行路径：开始 → 检索 → 生成 → 结束。
  • 价值：流程清晰，后续易扩展（如插入 rerank 节点）。

片段 H（L115-L153）main 前半：连接与加载 Milvus

vectorStore = await Milvus.fromExistingCollection(embeddings, { ... });
vectorStore.indexSearchParams = { ... };
await vectorStore.client.loadCollection({ collection_name: COLLECTION_NAME });
  • 含义：连接已有集合，配置检索参数，并确保集合被加载到内存。
  • 输入：集合名、Milvus 地址、向量字段配置、索引参数。
  • 容错：若已加载，捕获 already loaded 并继续执行。

片段 I（L155-L187）main 后半：执行图并打印结果

const result = await graph.invoke({ question, k, documents: [], generation: "" });
if (result.documents.length === 0) { ... } else { ... }
if (!result.generation) { ... }
  • 含义：真正触发 RAG 流程，并把检索命中与最终答案输出到控制台。
  • 输入：初始 state（问题 + 空 documents + 空 generation）。
  • 输出：控制台可读结果；函数本身不写文件。
  • 兜底：无检索命中和模型空输出都给出可读提示。

4) 运行时链路

  1. 初始化 LLM 与 Embeddings。
  2. 连接 Milvus 并尝试 loadCollection。
  3. 图执行进入 retrieve：按问题向量检索 top-k 片段。
  4. 图执行进入 generate：拼接上下文 Prompt 并流式生成。
  5. 控制台输出检索结果与最终回答。

5) 代码亮点

流式输出 图结构清晰 检索结果可观测 Milvus 加载兜底
  • 检索与生成解耦，便于后续插入重排、过滤、缓存节点。
  • 输出中包含 metadata，可定位知识片段来源。

6) 风险与改进建议

依赖风险

  • @langchain/community/vectorstores/milvus 依赖底层 SDK。
  • 若缺失 @zilliz/milvus2-sdk-node 会报 ERR_MODULE_NOT_FOUND。

可配置性

  • question 和 kArg 目前写死，建议改为 CLI 参数。
  • Milvus URL 建议改为环境变量。

健壮性

  • 可在启动时校验关键环境变量，提前失败并给出提示。
  • 建议为 vectorStore 未初始化场景添加保护。

检索质量

  • 可增加重排（rerank）和 chunk 邻域拼接。
  • 可按章节或书籍 ID 做 metadata 过滤以减少噪音。
