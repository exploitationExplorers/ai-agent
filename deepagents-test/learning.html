三个 Middleware（点 Tab）

生命周期钩子 + stateSchema 扩展 modelCallCount

createMiddleware({
  name: "LoggingMiddleware",
  stateSchema: z.object({
    modelCallCount: z.number().default(0),
  }),
  beforeAgent: (state) => { /* invoke 开始 */ },
  beforeModel: (state) => { /* 每次调模型前 */ },
  afterModel: (state) => {
    return { modelCallCount: state.modelCallCount + 1 }; // 写回 state
  },
  afterAgent: (state) => { /* invoke 结束 */ },
});
  • afterModel 必须 return 对象 才会累加；只 log 不算写 state
  • 多个 middleware：进 model 正向、出 model 反向（洋葱模型）
  • invoke 返回值里能直接解构 modelCallCount

wrap 型：包住模型调用，改当次 request

wrapModelCall: async (request, handler) => {
  return handler({
    ...request,
    systemMessage: request.systemMessage.concat(
      "\n\n 请用一句话简洁回答。"
    ),
  });
},
  • 必须调 handler(...)，否则模型不跑
  • 不等于永久改 systemPrompt
  • 适合：动态切模型、临时约束、重试、缓存

短路：跳过 model / tools，直接结束

beforeModel: {
  canJumpTo: ["end"],          // 先声明能跳哪
  hook: (state) => {
    if (text.includes("BLOCKED")) {
      return {
        messages: [new AIMessage("该请求已被 middleware 拦截，无法处理。")],
        jumpTo: "end",
      };
    }
  },
},
  • 写成函数 beforeModel: (s)=>{} 只能改 state，不能跳转
  • 要短路必须 { canJumpTo, hook } 对象形式
  • 命中后本次 modelCallCount 不会 +1

默写骨架

import "dotenv/config";
import { ChatOpenAI } from "@langchain/openai";
import { createAgent, createMiddleware, HumanMessage, AIMessage } from "langchain";
import { z } from "zod";

const model = new ChatOpenAI({ /* .env */ });
const mw = createMiddleware({ name: "...", /* hooks */ });

const agent = createAgent({
  model,
  tools: [],
  systemPrompt: "你是一个助手。",
  middleware: [mw],           // 顺序有意义
});

const result = await agent.invoke({
  messages: [new HumanMessage("...")],
});

三块机制（点 Tab）

工具定义在 middleware 上，agent 的 tools 可以是空数组

const getCurrentTime = tool(() => new Date().toISOString(), {
  name: "get_current_time",
  description: "返回当前 UTC 时间的 ISO 8601 字符串",
  schema: z.object({}),
});

createMiddleware({
  name: "ExtendedToolsMiddleware",
  tools: [getCurrentTime],   // 编译时并入 agent
  // ...
});

createAgent({
  tools: [],                 // 这里为空，模型仍看得到该工具
  middleware: [extendedToolsMiddleware],
});
  • tools 和 stateSchema 都是编译期配置，不是每次调用才挂上
  • 模型靠 name + description 决定要不要调；问「当前时间」是为了逼它走工具
  • 适合把一类能力（时间、待办、文件）打包成可复用 middleware

包住每一次工具执行：先 log，再 handler，再改返回值

wrapToolCall: async (request, handler) => {
  const toolName = request.tool?.name ?? request.toolCall.name;
  const result = await handler(request);          // 不调则工具不跑
  if (!ToolMessage.isInstance(result)) return result;

  return new ToolMessage({
    content: `${result.content}\n[wrapToolCall] 已包装`,
    tool_call_id: result.tool_call_id,            // 必须对上这次调用
    name: result.name,
  });
},
  • 必须调 handler(request)，否则工具函数不执行（也可故意不调，用来短路或换结果）
  • handler 可能返回 Command 而不是 ToolMessage，先 isInstance 再包装
  • tool_call_id 丢了，模型对不上这次 tool call
  • 改的是喂回模型的工具结果，模型第二轮可能把包装后缀写进回复

wrap 钩子要改自定义 state，返回 Command，不能像 afterModel 那样直接 return 对象

return new Command({
  update: {
    toolInvocationCount: request.state.toolInvocationCount + 1,
    messages: [wrapped],     // messages 是追加，不是整段替换
  },
});

afterAgent: (state) => {
  // 只读计数。这里 return 才会写 state，本案例只打印
  console.log(state.toolInvocationCount);
},
  • 只 return wrapped：工具结果进对话，toolInvocationCount 不会 +1
  • Command 里不带 messages：自定义字段会更新，但这条工具结果可能进不了对话
  • 计数发生在工具真正返回 ToolMessage 时；afterAgent 只是收尾打印
  • 一次 invoke 里模型通常会跑两轮（发 tool call、再读结果），工具计数仍是 1

默写骨架

import "dotenv/config";
import { Command } from "@langchain/langgraph";
import { z } from "zod";
import { ChatOpenAI } from "@langchain/openai";
import { createAgent, createMiddleware, HumanMessage, ToolMessage, tool } from "langchain";

const myTool = tool(async () => "ok", {
  name: "my_tool",
  description: "...",
  schema: z.object({}),
});

const mw = createMiddleware({
  name: "ExtendedToolsMiddleware",
  stateSchema: z.object({ toolInvocationCount: z.number().default(0) }),
  tools: [myTool],
  wrapToolCall: async (request, handler) => {
    const result = await handler(request);
    if (!ToolMessage.isInstance(result)) return result;
    const wrapped = new ToolMessage({ /* content, tool_call_id, name */ });
    return new Command({
      update: {
        toolInvocationCount: request.state.toolInvocationCount + 1,
        messages: [wrapped],
      },
    });
  },
});

const agent = createAgent({ model, tools: [], middleware: [mw] });
const { toolInvocationCount } = await agent.invoke({
  messages: [new HumanMessage("...")],
});

执行时序（对照终端 log）

用户消息 「给我当前时间」
模型第 1 轮 发出 tool call：get_current_time
wrapToolCall 即将执行 → handler → 包装 ToolMessage
Command.update：toolInvocationCount + 1，并把包装后的消息追加进 messages
模型第 2 轮 读到带后缀的工具结果，生成给用户的回复
afterAgent 打印工具调用 1 次；invoke 可解构 toolInvocationCount

这条用例在验证什么

会调工具

给我当前时间

  • 终端有「即将执行 / 执行完成」
  • 工具内容末尾有包装后缀
  • toolInvocationCount === 1

模型没调工具时

直接用文字回答

  • wrapToolCall 不会进
  • 没有包装后缀
  • 计数保持默认 0

和案例 1 一样：每次 invoke 的 state 独立。afterAgent 不 return，就不会改计数。

四块机制（点 Tab）

渐进披露：启动只塞 name/description，需要时再 read_file 全文

createSkillsMiddleware({
  backend,
  sources: ["/.agents/skills/"],   // virtualMode 下相对 rootDir
});

// 启动时：把各 SKILL.md frontmatter 注入 system prompt
// 任务匹配 description 后：模型自己 read_file 对应 SKILL.md
// 支持文件（scripts/references/assets）：按 SKILL 指示再读
  • sources 扫目录：每个含 SKILL.md 的子目录是一个 skill
  • state 里有 skillsMetadata（name / description / path），可从事件流捞到
  • 本案例缺 skill 会直接 throw，提示先 npx skills add ...
  • systemPrompt 写明「按 skills 库完成任务」，引导模型去读 SKILL.md

给 agent 挂上读/写/列目录等工具；skills 读全文也靠它

createFilesystemMiddleware({ backend });

// 常见工具：ls / read_file / write_file / edit_file / glob / grep
// LocalShellBackend 还会额外提供 execute（本案例主要靠读写文件）

createAgent({
  tools: [],                         // 工具仍来自 middleware
  middleware: [
    createSkillsMiddleware({ ... }),
    createFilesystemMiddleware({ ... }),
  ],
});
  • 顺序：Skills 在前（先注入目录），Filesystem 在后（提供读写）
  • 画图任务通常：read_file SKILL → 按说明生成 → write_file 到 output
  • mkdirSync("src/deepagents/output") 是 Node 侧预建目录，避免写文件失败

Backend 是「虚拟根文件系统」；middleware 不直接碰本机路径语义

const backend = await LocalShellBackend.create({
  rootDir: ".",
  virtualMode: true,   // "/.agents/skills/" → ./.agents/skills/
  inheritEnv: true,    // shell 继承当前环境变量
});

// ...跑完后
await backend.close();
  • virtualMode: true：路径以 / 开头，被限制在 rootDir 下
  • LocalShellBackend = 本机文件系统 + 无沙箱 shell；只适合本地 demo
  • create() 会 initialize；结束记得 close()
  • 生产环境应换 StateBackend / StoreBackend / Sandbox，不要用 LocalShell

用 streamEvents 看 token 和工具调用，而不是等 invoke 结束

const stream = await agent.streamEvents(
  { messages: [new HumanMessage(prompt)] },
  { recursionLimit: 100 },
);

for await (const event of stream) {
  if (event.event === "on_chat_model_stream") {
    process.stdout.write(chunkText(event.data?.chunk));
  }
  if (event.event === "on_tool_start") {
    process.stdout.write(`\n\n→ ${event.name}\n\n`);
  }
  if (event.event === "on_chain_end" && event.data?.output?.skillsMetadata) {
    skillsMetadata = event.data.output.skillsMetadata;
  }
}
  • streaming: true + on_chat_model_stream：边生成边打字
  • on_tool_start：看见 agent 何时 read_file / write_file
  • recursionLimit: 100：多轮工具调用时放宽图递归上限
  • 最后检查 existsSync(output) 确认图表是否落盘

执行时序（对照终端）

启动 LocalShellBackend.create → 扫描 /.agents/skills/
Skills L1 name/description 注入 system prompt
用户 Prompt 画 skills-agent 工作流，保存为 .excalidraw
Skills L2 → read_file …/excalidraw-diagram-generator/SKILL.md
按 SKILL 说明生成图表 JSON/内容 → write_file 到 src/deepagents/output/...
收尾 打印 skillsMetadata；backend.close()

这条用例在验证什么

成功路径

  • skill 已安装，能匹配「画流程图 / excalidraw」
  • 流式输出里出现工具名
  • 目标 .excalidraw 文件存在
  • skills: 打印含 skill 名

常见失败

  • 缺 SKILL.md → 启动即 throw
